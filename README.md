# hexview

Учебная консольная утилита на C11 для просмотра содержимого файлов в hex-формате.
Сейчас есть только каркас: программа собирается и завершается с кодом 0.
Описанное ниже поведение — предлагаемое ТЗ для последовательной реализации.

## Что должна делать программа

Команда `hexview FILE` читает файл как последовательность байтов и показывает:

- смещение от начала файла в шестнадцатеричном виде;
- значения байтов: по 16 на строку, два hex-символа на байт;
- текст справа: байты от `0x20` до `0x7e` как ASCII, остальные как `.`.

Например, файл с байтами `Hi\n` должен выглядеть так:

```text
00000000  48 69 0a                                         |Hi.|
```

Смещение занимает минимум 8 hex-цифр. Hex-цифры строчные. Между байтами один
пробел; после последней позиции байта — два пробела перед `|`. В неполной строке
незаполненные позиции hex-колонки заменяются пробелами, чтобы `|` всегда была
в одной колонке. ASCII-часть содержит только прочитанные байты, без дополнения.
После каждой строки — перевод строки. Финальная строка только со смещением
не нужна; повторяющиеся строки не сжимаются. Пустой файл не даёт вывода.

Результат идёт в stdout, ошибки — в stderr. Успех означает код завершения 0,
ошибка — ненулевой код. На первом этапе нужен ровно один аргумент — путь к файлу.
Чтение stdin, флаги, цвета и интерактивный редактор пока вне задачи.

## Сборка

Нужны CMake 3.15+ и компилятор C (GCC или Clang).

```sh
cmake -S . -B build
cmake --build build
./build/hexview
```

Пока последняя команда только запускает каркас; после реализации потребуется
путь к файлу. `make build` и `make run` используют ту же сборку CMake.
После появления аргументов запускай `./build/hexview FILE` напрямую.
CI собирает проект на Ubuntu отдельно с GCC и Clang; предупреждения компилятора
считаются ошибками (`-Wall -Wextra -Wpedantic -Werror`).

## План небольших PR

1. **Сборка и ТЗ.** Исправить цель CMake, согласовать Makefile и CI, описать задачу.
2. **Аргументы и открытие файла.** Проверить число аргументов, открыть файл через
   `fopen(path, "rb")`, закрыть его. Ошибки использования и открытия вывести в
   stderr и вернуть ненулевой код. Пока содержимое не печатать.
3. **Чтение и hex-байты.** Читать через `fread` в буфер `unsigned char[16]`, печатать
   только байты (`48 69 0a\n` для `Hi\n`), по 16 на строку. Обработать последнюю
   неполную строку, пустой файл и `ferror`. Не загружать весь файл в память.
4. **Полный формат.** Добавить смещение, выравнивание и ASCII-колонку по ТЗ выше.
5. **Регрессионные проверки.** Добавить проверки CLI в CTest и запуск в CI:
   пустой файл, 1/15/16/17 байтов, `00 7f 80 ff`, неверные аргументы,
   отсутствующий файл и ошибка записи stdout. Обработать ошибки вывода.

В каждом PR проверяем только добавленное поведение, обсуждаем код и после
слияния берём следующий шаг. Реализацию шагов 2–5 делает автор проекта.
